# Requisitos Não-Funcionais

[Voltar](../DOCUMENTACAO.md)
 
| **Código** | **Categoria** | **Nome do Requisito** | **Descrição Detalhada (Critério de Aceite)** | **Prioridade** |
| --- | --- | --- | --- | --- |
| **NFR001** | **Desempenho** | Tempo de Resolução de Transações | O cadastro de um pedido, alteração de status ou fechamento de comanda deve ser processado e refletido na interface em no máximo **2 segundos**. Relatórios financeiros (Dashboard) devem carregar em até **5 segundos** com filtros padrão. | **Alta** |
| **NFR002** | **Desempenho** | Concorrência (Horário de Pico) | O sistema deve suportar **no mínimo 30 usuários simultâneos** (garçons cadastrando pedidos, caixas fechando contas e gerente visualizando relatórios) sem queda de performance ou timeout nas requisições. | **Alta** |
| **NFR003** | **Usabilidade / UX** | Responsividade (Mobile First) | A interface deve se adaptar perfeitamente a telas a partir de **360px de largura** (smartphones) até telas 4K. Os botões de ação (ex: "Adicionar Item", "Fechar Comanda") devem ser grandes e de fácil toque no mobile, pois o garçom usa o sistema em pé e com alta rotatividade. | **Alta** |
| **NFR004** | **Usabilidade / UX** | Eficiência do Garçom (Lei de Fitts) | O fluxo de "Abrir Comanda + Adicionar Pedido" deve exigir no máximo **3 cliques/toques** a partir da tela inicial, para não atrasar o atendimento ao cliente. | **Média** |
| **NFR005** | **Confiabilidade** | Consistência Transacional (ACID) | Operações financeiras (fechamento de comanda, baixa de estoque) devem ser **atómicas**. Se uma etapa falhar (ex: imprimir a nota, mas não debitar o estoque), o sistema deve realizar *rollback* total, garantindo que não haja comandas "fantasmas" ou valores duplicados. | **Alta** |
| **NFR006** | **Confiabilidade** | Tolerância a Falhas de Impressão | O sistema deve possuir uma **fila de impressão local/remota**. Se a impressora da cozinha estiver offline ou sem papel, o pedido não pode ser perdido. O sistema deve armazenar o pedido na fila e reimprimir automaticamente assim que a impressora se reconectar, ou exibir um alerta sonoro/visual para o caixa. | **Alta** |
| **NFR007** | **Confiabilidade** | Backup e Recuperação de Dados | O banco de dados deve ter backup automatizado diário (em horário de menor movimento, ex: 04:00). A recuperação de dados em caso de desastre deve ser concluída em até **1 hora**, com perda máxima de dados de **15 minutos** (RPO e RTO definidos). | **Alta** |
| **NFR008** | **Segurança** | Criptografia de Dados Sensíveis | As senhas dos funcionarios (tabela `Funcionario`) devem ser armazenadas utilizando hash forte (ex: **bcrypt** ou **Argon2**). Dados de CPF e telefone dos clientes (`Perfil`) devem ser criptografados no banco de dados (ou ao menos mascarados em logs). | **Alta** |
| **NFR009** | **Segurança** | Controle de Sessão (Timeout) | A sessão do usuário deve expirar automaticamente após **30 minutos** de inatividade em qualquer dispositivo, exigindo novo login para retomar as operações, evitando acessos indevidos em dispositivos compartilhados. | **Média** |
| **NFR010** | **Segurança / LGPD** | Privacidade e Direito ao Esquecimento | O sistema deve permitir que o Gerente **anonimize** ou **exclua** permanentemente os dados de um cliente (tabelas `Cliente` e `Perfil`) quando solicitado, respeitando a Lei Geral de Proteção de Dados (LGPD), sem prejudicar a integridade dos históricos de venda (mantendo apenas o ID anônimo). | **Média** |
| **NFR011** | **Manutenibilidade** | Rastreabilidade (Logs Estruturados) | Todas as ações críticas (exclusão de produto, alteração de cargo, fechamento de comanda com valor alterado manualmente) devem gerar logs com **timestamp**, **ID do usuário** e **IP da máquina**. Os logs devem ser armazenados por no mínimo **180 dias** para auditoria. | **Média** |
| **NFR012** | **Portabilidade / Suporte** | Compatibilidade de Navegadores | O sistema WEB deve ser totalmente funcional nas últimas **2 versões estáveis** dos navegadores: Google Chrome, Mozilla Firefox, Microsoft Edge e Safari (tanto no iOS quanto no macOS). | **Alta** |
| **NFR013** | **Disponibilidade** | Uptime e Manutenção Programada | O sistema deve ter disponibilidade mínima de **99,5%** em horário comercial (11:00 às 23:00). Manutenções programadas que exijam *downtime* devem ser agendadas para o período da madrugada (00:00 às 05:00) e comunicadas aos gestores com 48h de antecedência. | **Alta** |
| **NFR014** | **Arquitetura** | Desacoplamento de Serviços (Impressão) | O módulo de impressão deve ser desacoplado da lógica principal de negócio (ex: usar WebSockets ou Filas). Isso impede que uma falha na impressora trave o cadastro de um novo pedido; o pedido é salvo primeiro e, em segundo plano, enviado para impressão. | **Alta** |
